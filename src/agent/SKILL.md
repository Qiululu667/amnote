# AM·Note 笔记库

用户的笔记在本地文件夹里，AM·Note 给它们建了全文索引。命令行工具是
`{{AMNOTE_BIN}}`。**笔记可能分在几个笔记本里**（一个笔记本＝用户加进来的一个
文件夹），所以开工第一句是 `{{AMNOTE_BIN}} notebooks`：

- 只有一本时：路径就是**库相对路径**（`工作手记/报销.md`）。
- 有好几本时：路径**以笔记本名开头**（`工作/会议/周会.md`），你发过去的路径
  也要这么写，不带前缀会被退回。同一个文件名在两本里各有一份是常事，
  别猜是哪一本的——搜索结果里那条路径已经写明了。

两种情形下路径都不是绝对路径。

## 先看有哪些本，再看地图，再搜，最后只读要的那一节

```sh
{{AMNOTE_BIN}} notebooks                     # 有哪些笔记本、哪本是默认（✓）
{{AMNOTE_BIN}} map                           # 有哪些目录、每篇讲什么（多本时一本一节）
{{AMNOTE_BIN}} map -n 工作                    # 只看「工作」这一本
{{AMNOTE_BIN}} search "报销 流程" -n 10       # 空格分开＝AND；这里的 -n 是「要几条」
{{AMNOTE_BIN}} search "报销" --notebook 工作  # 只搜一本
{{AMNOTE_BIN}} outline 工作/工作手记/报销.md   # 这份有哪些小节
{{AMNOTE_BIN}} read 工作/工作手记/报销.md --section 发票
```

**`search` 和 `recent` 上的 `-n` 是「要几条」**（一直是这样），所以这两条命令
限定笔记本要写全 `--notebook 名字`；`map` / `tree` / `read` / `outline` /
`links` / `new` / `save` / `trash` 上 `-n 名字` 就是笔记本。吃路径的那几条上
`-n` 只是替你补前缀：`read -n 工作 会议/周会.md` ＝ `read 工作/会议/周会.md`
（路径已经带着这一本的前缀就不重复补；**`-n` 说了算**，所以别把 `-n` 和
另一本的前缀路径混着写）。

`search` 每条命中下面是片段，`L12 [打包] …前【中】后…` 里的 `L12` 是行号、
`[打包]` 是所在小节——照着它 `read --section 打包`，别整篇读回来。
筛选：`--dir 目录`（多本时写成 `工作/会议`，前缀等于限定了那一本）、
`--type md,pdf`、`--since 7`（最近 7 天）或 `--since 2026-09-01`。

其他几条：`{{AMNOTE_BIN}} recent --days 7`（最近改了什么）、
`{{AMNOTE_BIN}} links <路径>`（谁引用了它）、`{{AMNOTE_BIN}} tree`（全部文件）。

## 写笔记：读 → 改 → 整篇写回

```sh
{{AMNOTE_BIN}} new "会议纪要 0906" <<'EOF'   # 不给 --dir 就放随手记目录
# 会议纪要 0906
…
EOF
{{AMNOTE_BIN}} new "本月书单" -n 读书          # 落到「读书」那本的随手记目录
{{AMNOTE_BIN}} new "月度复盘" --dir 工作/工作手记 --body-file /tmp/draft.md
{{AMNOTE_BIN}} read 工作/工作手记/报销.md > /tmp/new.md    # ← 先读，这一步不能省
{{AMNOTE_BIN}} save 工作/工作手记/报销.md --body-file /tmp/new.md   # 改完整篇覆写
{{AMNOTE_BIN}} trash 工作/随手记/写错了.md      # 挪进废纸篓，不是删掉
```

新建落在哪一本：`-n 名字` 说了算；不给就是 `notebooks` 里标了 ✓ 的那本
（**不看你刚才在读哪一本**）。落点会打印出来，照着它往下走。

`save` 是**整篇覆写**，而且**必须先 `read` 过这一份**：`read` 会记下你看到的
是哪一版，`save` 拿它当「基于」交给服务端做冲突检测。没读过就 `save` 会退出码
1，说「先 amnote read 这份，或加 `--based`/`--force`」——那不是啰嗦，是在拦
「不知道原来写了什么就一把盖掉」。手上已经有那一版的「改于」（`read --json`
里那个字段）也可以直接 `--based "2026-09-06 17:20:31"`。

退出码 3 ＝ 这份在你读完之后被别处改过了。这时**先停下告诉用户**，
重新 `read` 一遍合并；确实要盖掉那次改动才加 `--force`。

写请求会记进变更流水并署上你的名字，用户在 AM·Note 里看得到是谁改的。

## 几条规矩

- 不要 `grep` / `find` 笔记文件夹，也不要直接改文件——搜索走索引，写走 `save`，
  这样才有备份、流水和冲突检测。
- 用户在 AM·Note 界面上勾一个 `- [ ]` 待办会**当场改那份文件**，不经过你：
  所以 `save` 之前一定是刚 `read` 过的那一版，隔了一会儿就重读一遍再写；
  拿到退出码 3（冲突）就重读、合并、再写，别 `--force` 盖掉用户刚勾的那一下。
- `.amnote/` 是 AM·Note 自己的目录（索引、备份、配置），每个笔记本各有一份，
  不看也不动。
- `~/Library/Application Support/AMNote/notebooks.json` 是笔记本名单，
  AM·Note 自己管着，**别去改它**；要加要减让用户在设置里做。
- 退出码：0 成功 · 1 用法错（含「还没 read 过」）· 2 AM·Note 没在运行
  （或者找不到你说的那个笔记本）· 3 冲突 · 4 服务端拒绝。
  遇到 2：只读的几条会自动用上一次的索引（结果可能旧一点，而且只认一本），
  写不了，请用户打开 AM·Note。
- 每条命令都能加 `--json`，要结构化结果时用它（`tree -n 名字` 是在本地筛，
  `--json` 出的是筛完那份）。
- 真要直接打门户接口取增量（`/__changes`）：**「序号」是各本自己的号、跨本不
  唯一**，`since=` 也按本各自算——按序号取增量就一次只问一本（`nb=名字`）。
- 不确定用户指的是哪一份、哪一本时，先 `search` 列几条给用户挑，别猜着改。
